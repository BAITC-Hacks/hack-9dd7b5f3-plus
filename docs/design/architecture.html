Bagyt, under the hood

A web voice robot for the Saqta Insurance contact center. The client speaks Russian, Kazakh, or both in one phrase. An LLM routing layer picks one of 40 scenarios from the dialog context, and the robot answers by voice. The admin console shows every decision and every millisecond live.

OVERALL

One pipeline, three channels

The browser user, a phone caller, and the admin console all connect to one Go gateway. Every utterance runs through the same turn pipeline, and every stage emits a timed event. The same event stream drives the admin console and Postgres.

route → { scenario_id: "SC12", confidence: 0.88, alternatives: [SC11 0.20], stack: [SC26], language: "mixed", action: "proceed", slots: { accident_date: "2026-09-30" } }
THE 1.5 SECOND BUDGET

Where the milliseconds go

The clock starts when the client stops speaking. STT streams during speech, so most of the transcript is already there at t = 0. The robot starts talking as soon as the router has picked a scenario.

saves 300–800 ms

Stream STT during speech

WebSocket audio frames go out while the client is still talking. Only the last words remain at t = 0.

saves 200–500 ms

Push-to-talk on web

Releasing the button marks the end of speech exactly, with no VAD silence wait. VAD runs only on the phone and in hands-free mode.

hides 200–400 ms

Speculative routing

Route on a stable partial transcript. If the final text changes, cancel and re-run.

router 250–450 ms

Cached prompt, tiny JSON

Static prefix (rules + catalog) first so prompt caching applies; temperature 0, ~200 output tokens, strict schema.

first sound ≈ 0.6 s

Pre-synthesized openings

At boot: 40 scenarios × RU/KZ opening lines → audio cache. Play one the moment the router decides.

−1 LLM call

Fast path from the dataset

fast_path_eligible scenarios (SC18, 23, 24, 26, 31, 33, 34, 36, 37) answer from a KB template.

overlaps 300+ ms

Sentence-level streaming

The reply LLM emits the first sentence → TTS starts while the LLM writes the second.

avoids 5–30 s spikes

Keep providers warm

geko GPUs scale to zero. Ping STT/TTS/LLM on page load and every 2 min during the demo.

TWO HARD PROBLEMS

Picking the scenario and the language in real time

The router must work out what the caller needs while they are still talking, without jumping to a wrong scenario. The robot must also answer in the right language even when the caller mixes Russian and Kazakh.

What

A projector view: dial number and QR on the left, the live call on the right. Words tinted by language, route chips, and a latency ticker that turns green under budget.

How

A call event opens the card. partial streams the words. Per-word language comes from STT tokens when the vendor provides it, otherwise from a letter check: ә ғ қ ң ө ұ ү һ і ⇒ Kazakh.

Speed

Pure client rendering of existing events, with no extra model calls. The ribbon updates with each partial (~100–200 ms) and the ticker fills as timing events land.

All 40 scenarios as a map grouped by category. The active scenario lights up, alternatives glow by confidence, and each topic switch draws an arc onto the stack.

PROVIDERS

STT, TTS and LLM: what we pick and why

Everything sits behind STT, TTS and LLM interfaces chosen by env var, so switching is a config change. Vendor latencies are their published figures; we run a 15-minute bake-off on our own phrases before we commit.

Proposed default: Soniox RT (STT) → gpt-4.1-nano router (JSON) → gpt-4.1-mini reply stream → geko Tokay for Kazakh / ElevenLabs Flash v2.5 for Russian. geko Seta is the Kazakh accuracy A/B. Browser STT/TTS plus the mock router serve as the keyless mode for reviewers.

15-minute bake-off, before we commit

  1. Record 3 phrases on the venue laptop mic: simple RU, pure KZ, mixed RU+KZ (the accident + policy phrase above).
  2. Run each through Soniox, geko Seta and Scribe v2. Log time to final and eyeball the words.
  3. Synthesize one KZ and one RU reply with Tokay, Flash v2.5 and Soniox TTS. Log first-chunk ms.
  4. Pick per language and put the numbers in the README; the jury rewards measured claims.
