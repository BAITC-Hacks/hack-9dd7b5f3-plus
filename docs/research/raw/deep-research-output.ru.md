# HackAlem — Команда «Plus» — Voice Router (Halyk Bank, Case 2). Build-пакет.

> Единственный источник истины на время сборки. Всё, помеченное **ASSUMPTION**, нужно проверить в живых доках перед тем, как заявлять жюри.

## TL;DR
- **Строим «Bagyt» (Бағыт)** — веб-симулятор голосового робота, где выбор из 40 сценариев делает **LLM-слой** (retrieval-шортлист + генеративный JSON-роутер в стиле Rasa CALM command generation), а **НЕ** энкодерный intent-классификатор. Голос RU/KZ с переключением языка внутри фразы обеспечивает **geko.sh** (Seta STT / Tokay TTS), fallback — **ElevenLabs Scribe v2 Realtime**.
- **Speko вырезаем из ядра**: он бенчмаркит и маршрутизирует ~10 языков, среди которых **нет казахского и русского** — значит для KZ/RU-пути он бесполезен (оставляем только опционально/для дизайн-системы). «Свою модель роутинга» тоже режем: по ТЗ преимущества не даёт, а энкодерные классификаторы запрещены.
- **Ориентир 500мс на выбор сценария** достижим нестабильно (один облачный TTFT LLM уже ~0.45–0.6с) — честно измеряем по этапам, показываем в UI, добираем скорость speculative-роутингом на частичных транскриптах. **Телефон — только stretch после P0.**

## Key Findings
- **geko.sh — решающий провайдер для KZ/RU.** Одна STT-модель **Seta-1.0 (seta-kk-ru-v2)** слушает казахский и русский «в одном словаре», с переключением «mid-sentence, and inside a word» (посреди фразы и внутри слова); заявленный **WER 8.71%** против **Whisper 44.95%** на том же казахском аудио, «40× faster than real time». TTS **Tokay-1.0 (tokay-kk-v1)** — WAV 24кГц 16-бит PCM mono, стриминг по предложениям, числа проговаривает словами (важно для страховых сумм). Эндпоинты **OpenAI-совместимые** (`/v1/audio/speech`, `/v1/audio/transcriptions`, `/v1/transcribe`, `/v1/tts/stream`) — «меняешь base URL и model». Пилоты уже живут в Kcell, Beeline, Oneshott Coffee. Минусы: GPU-бэкенды scale-to-zero → возможен холодный старт (величина — **ASSUMPTION**, проверить); число казахских голосов Tokay на демо подтвердить по датащиту (**ASSUMPTION** — на главной не подтверждено явно).
- **ElevenLabs Scribe v2 Realtime** — стриминговый STT с заявленной задержкой ~150мс, казахский и русский в категории High Accuracy (>5%…≤10% WER); хороший primary по латентности и fallback к geko.
- **Роутер без энкодера.** Retrieval (эмбеддинги примеров из scenarios.json) только **шортлистит** кандидатов — это не классификация. Окончательный выбор и обоснование делает генеративная LLM, выдавая строгий JSON/команды — ровно подход Rasa **CALM CommandGenerator** («intentless», по контексту всего диалога). Это и есть требуемый «LLM-слой».
- **LLM для роутинга.** **gpt-4.1-nano** — в независимом eval (MemX, 2026) 100% валидного JSON-schema, P50 ~1.25с, P99 3.4с, дешевле gpt-4o-mini; поддерживает structured output через json_schema/function-calling. TTFT у OpenAI-класса ~0.45–0.6с (EdenAI 2026: GPT-4o TTFT p50 ~450мс). Для «fast tier» — **Groq/Cerebras** (TTFT ~80–150мс на прогретых эндпоинтах, но с риском по KZ/RU-качеству и без гарантии на холодную). Альтернатива — **Gemini 2.5 Flash-Lite** ($0.10/$0.40 за 1М, оптимизирована под классификацию/перевод/низкую задержку).
- **Speko** (YC S26, «OpenRouter for Voice», основатель Bek): база `router.speko.dev` (в опенсорс-гейтвее также `relay.speko.dev` — **несогласованность, проверить**); контракт `POST /v1/stt/transcriptions`, `/v1/tts/speech`, `/v1/llm/responses`; интент задаётся `optimizeFor=balanced|accuracy|latency|cost` (в гейтвее — `objective=quality|latency|cost|balanced`), `language`, `region`; пиннинг `provider:model`; ответ в заголовках `Speko-Provider/Model/Region/Attempt-ID`; официальные SDK `@spekoai/sdk` и `spekoai` (PyPI); адаптеры LiveKit/Pipecat/Vapi/Retell. **Но KZ/RU не входят в его бенчмаркуемые языки** (published set: EN, AR, FR, DE, HI, NB, ES, TA, TE + один неотображённый) → не для нашего ядра.
- **VAD/barge-in.** Стандарт — **Silero VAD** (кадры ~32мс) для endpoint-детекции и barge-in; barge-in гейтить по VAD, не по STT-партиалам (STT слишком медленный для триггера). WebRTC VAD — лёгкий fallback.
- **Speculative routing.** Запуск роут-цепочки на стабильном частичном транскрипте (conf STT >0.85) с отменой устаревших вызовов даёт −200…400мс P95 (Pipecat/Futureagi 2026); реально скрывает задержку выбора сценария к моменту конца реплики.
- **Телефон.** Быстрейший путь сегодня — **Vapi + номер Twilio** (порт/покупка номера доступной страны) либо **LiveKit SIP inbound** с нашим `/api/route` как «мозгом». KZ **+7** с KYC за окно сборки не поднять (**ASSUMPTION**) — на демо показываем на не-KZ номере либо оставляем как архитектурный план в README.

# PRD.md — «Bagyt» (Бағыт)

**Название:** Bagyt (каз. «маршрут/направление») — читается на RU и KZ, прямая метафора маршрутизации.
**One-liner:** Голосовой AI-робот контакт-центра, который с первой реплики понимает суть на русском и казахском (даже при переключении внутри фразы), сам выбирает и переключает сценарий LLM-слоем и показывает супервизору, почему и за какое время он это сделал.

## Персоны
- **Клиент контакт-центра (страховая):** говорит своими словами; хочет закрыть вопрос без оператора; может сменить тему и смешать языки.
- **Супервизор:** хочет видеть, какие сценарии выбирались, где робот сомневался/ошибся, задержки по этапам, статистику ошибок.

## Приоритеты
### P0 (обязательное, до 16:00)
- Веб-микрофон + текстовый резервный ввод.
- Стриминговый STT (RU/KZ), выбор языка ответа.
- Retrieval-шортлист по scenarios.json + LLM-JSON-роутер (scenario_id, confidence, reasoning, alternatives).
- Голосовой ответ TTS.
- Панель трассировки (транскрипт, сценарий, обоснование, альтернативы, задержки по этапам).
- /api/route + интеграция evaluate.py; запуск docker compose одной командой; MOCK_MODE.

### P1 (ценность, 16:00–17:00)
- Стек тем: topic_switch/return_to_topic, мульти-интент (пример с оплатой+адресом).
- action: proceed|clarify|handoff; передача оператору с контекстом.
- Извлечение параметров (extracted_params).
- Fast-path (очевидные запросы) с замером Δ.
- Панель супервизора со статистикой ошибок и accuracy-отчётом.

### P2 (stretch, только если P0+P1 стабильны)
- Speculative routing на партиалах; цель 500мс; prompt caching.
- Эскалация на сильную LLM при низкой confidence.
- Редактирование каталога сценариев в UI.
- Телефонный канал (Vapi/Twilio/LiveKit).

## Демо-сценарий (3 минуты)
1. **Простой RU:** «Здравствуйте, хочу узнать статус моей заявки на страховку.» → роутер выбирает сценарий «статус заявки», confidence высокий, ответ голосом + трасса.
2. **Смешанная речь (официальный пример):** «Здравствуйте, я вчера оплатил, деньги списались, а заказ не подтвердился… а, и ещё, адрес доставки поменять надо.» → робот видит два интента, кладёт «изменение адреса» в стек тем, сначала закрывает оплату/подтверждение, потом возвращается к адресу.
3. **Казахский (KZ):** «Сәлеметсіз бе, полисімнің мерзімін ұзартқым келеді.» → выбор сценария продления полиса, ответ на казахском (Tokay).
4. **Стык сценариев + неуверенность:** пограничная реплика → confidence низкий → робот переспрашивает (clarify) вместо угадывания; показываем альтернативы.
5. **Смена темы + KZ↔RU внутри фразы:** «Менің шотымнан ақша списалось, помогите разобраться.» → корректный роут, язык ответа по доминирующему языку.
6. Открываем панель супервизора: accuracy по dev_utterances.json, задержки по этапам, где робот сомневался.

## Алгоритм роутера (пошагово)
1. Получаем финальный (или стабильный частичный) транскрипт + язык.
2. Эмбеддинг реплики → косинус к предвычисленным векторам примеров из scenarios.json → top-K (K=5–8) кандидатов. Это ШОРТЛИСТ, не решение.
3. Собираем промпт: системная роль + контекст диалога (последние N реплик + стек тем) + K кандидатов (id, назначение, границы) + инструкция вернуть строгий JSON.
4. LLM (gpt-4.1-nano) возвращает JSON-schema-выход. Если confidence < 0.6 → эскалация на gpt-4o (или переспрос).
5. Обновляем стек тем (topic_switch/return_to_topic), логируем route_decisions + stage_timings.
6. Ответ: action=proceed → генерируем реплику по knowledge_base/mock_backend + TTS; clarify → уточняющий вопрос; handoff → передача оператору с контекстом.
7. (P2) Fast-path: если top-1 косинус > 0.85 И нет маркеров смены темы → короткий путь без большой LLM, замер Δ; корректность всё равно валидируется LLM-путём.
8. (P2) Speculative: запускаем шаг 2–4 на стабильном партиале (>0.85 conf STT), отменяем устаревшие вызовы (−200…400мс P95).

## Черновик промпта (route)
```
Ты — слой маршрутизации контакт-центра страховой компании. Тебе даны:
- контекст диалога (реплики + активный стек тем),
- КАНДИДАТЫ сценариев (id, назначение, границы с соседями),
- последняя реплика клиента (может смешивать RU/KZ).
Не угадывай. Выбери сценарий ТОЛЬКО из кандидатов. Если реплика содержит
несколько намерений — верни основной + отметь остальные в topic_switch.
Если уверенность низкая или реплика на стыке — action="clarify".
Верни СТРОГО JSON по схеме. Обоснование — на языке клиента, кратко.
```

## Модель данных (Postgres)
- `sessions(id, created_at, lang_pref, channel)`
- `turns(id, session_id, idx, role, transcript, lang, created_at)`
- `route_decisions(id, turn_id, scenario_id, confidence, reasoning, alternatives jsonb, extracted_params jsonb, topic_switch, return_to_topic, action, model, escalated bool)`
- `stage_timings(id, turn_id, stage, ms)` — stage ∈ {vad_end, stt_final, shortlist, llm_route, llm_answer, first_tts_byte}

## WebSocket + REST (≤10)
1. `POST /api/session` → `{session_id}`.
2. `WS /ws/voice?session_id=` — вход: бинарные PCM16-кадры + `{type:"end"}`; выход: `{type:"partial|final",text}`, `{type:"route",decision}`, `{type:"tts",audio_b64|url}`, `{type:"timing",stage,ms}`.
3. `POST /api/route` — `{session_id, text, lang?}` → полный decision JSON. **Этот эндпоинт вызывает evaluate.py.** Детерминирован при MOCK_MODE=1.
4. `GET /api/session/{id}/trace` → массив turns+route_decisions+timings.
5. `GET /api/supervisor/stats` → `{accuracy, by_scenario, low_confidence_count, avg_timings}`.
6. `POST /api/eval/run` → прогоняет dev_utterances.json через роутер → `{accuracy, per_utterance[], latency_p50, latency_p95}` (в UI и README).
7. `GET /api/scenarios` → каталог (для UI и P2-редактора).
8. `POST /api/tts` — `{text, lang}` → audio (MOCK: канонический wav).
9. `GET /api/health` → `{ok, mock_mode}`.
10. `GET /api/config` → флаги.

```json
  "return_to_topic":"change_delivery_address","language":"ru","action":"proceed" }
```

## Интеграция evaluate.py / dev_utterances.json
- evaluate.py шлёт POST /api/route на каждую размеченную реплику, сравнивает scenario_id с меткой, считает accuracy. Добавляем /api/eval/run как обёртку — жюри одним кликом видит accuracy+latency в UI и README.
- Проверочные реплики жюри НЕ хранятся в коде; роутер решает динамически по scenarios.json.

## Панель трассировки и супервизор (UI)
- **TracePanel (после каждой реплики):** транскрипт, выбранный сценарий + обоснование, альтернативы с confidence, таблица stage_timings (мс по этапам), бейджи topic_switch/return_to_topic/language/action.
- **Supervisor:** таблица сессий, accuracy по dev_utterances, топ ошибок и «сомнений» (confidence<0.6), средние задержки, фильтры по сценарию.

## MOCK_MODE
- `MOCK_MODE=1`: STT/TTS/LLM заменяются детерминированными стабами (STT возвращает текст запроса; роутер — правило-эмбеддинг без внешних ключей; TTS — заранее записанный wav). Жюри тестирует /api/route, /api/eval/run и UI без ключей команды.

## 8 тяжёлых вопросов жюри + ответы
1. **«Чем это не intent-классификатор?»** — Эмбеддинги только шортлистят кандидатов (retrieval). Решение и обоснование генерирует LLM в виде команд/JSON (Rasa CALM-подход). Классификатора в точке решения нет.
2. **«Вы не захардкодили ответы под 10 реплик жюри?»** — Нет. Реплик в коде нет; роутер читает scenarios.json динамически, эмбеддинги строятся из него на старте. Можно подставить любые реплики.
3. **«500мс держите?»** — Это ориентир за доп.баллы, не условие. Честно: один облачный TTFT LLM ~0.45–0.6с, поэтому полный роут ~500–900мс; показываем реальные замеры и speculative-путь, скрывающий задержку до конца реплики.
4. **«Казахский реально работает или для галочки?»** — geko Seta слушает KZ/RU в одном словаре с переключением внутри слова (WER 8.71%); две KZ-реплики и смешанная — часть демо.
5. **«Что при ошибке роутера?»** — Низкая confidence → переспрос или передача оператору с контекстом. AI не единственный источник истины.
6. **«Масштабируется на 40+ сценариев?»** — Шортлист держит промпт коротким независимо от числа сценариев; добавление сценария = запись в scenarios.json, кода не трогаем.
7. **«Почему не своя модель?»** — По ТЗ преимущества не даёт, а энкодерные классификаторы запрещены; фокус на качестве LLM-маршрутизации, а не на обучении модели.
8. **«Необратимые действия?»** — Робот не выполняет их без явного подтверждения клиента; в трассе видно, что и почему предлагается.
