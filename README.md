# Voice Router — Team Plus · HackAlem AI · кейс Halyk Bank

> Трек 09 · Коммуникации · **Voice Router**: голосовой робот для контакт-центра страховой компании, в котором сценарий разговора выбирает **LLM-слой, понимающий контекст диалога**, а не энкодерный intent-классификатор. Русский и казахский (включая смешанную речь), голос на входе и на выходе, панель трассировки для супервизора: *что* выбрано, *почему* и *за какое время*.
>
> English version: [README.en.md](README.en.md) · Deployed-версия: `<не развёрнута>` · Доступ для проверки: не нужен — режим без ключей работает из коробки

## 1. Кратко

Клиент говорит в микрофон (или пишет текстом). Робот понимает суть с первой реплики, держит контекст до 10 реплик, переключается на новую тему и возвращается к прерванной, переходит между русским и казахским, переспрашивает вместо того чтобы угадывать, передаёт разговор оператору с кратким контекстом, когда это нужно, и никогда не выполняет необратимое действие без явного «да». После каждой реплики супервизор видит выбранный сценарий, обоснование, альтернативы, извлечённые параметры, выполненные действия и замеры по этапам относительно двух ориентиров (**выбор сценария ≤ 500 мс**, **конец реплики → начало ответа ≤ 1,5 с**).

Все 40 сценариев + 3 системных интента, слоты, действия, база знаний и тестовый бэкенд взяты из стартового кита организаторов в [`data/`](data/) (вымышленная страховая **Saqta Insurance**, синтетические данные). Проверочные реплики жюри нигде не захардкожены: роутер читает `scenarios.json` при старте (и по `POST /api/catalog/reload`).

## 2. Что реализовано

| Требование | Как сделано |
|---|---|
| Голосовое взаимодействие в вебе | Микрофон → PCM16 16 кГц по WebSocket → STT (ElevenLabs Scribe v2 **realtime** с промежуточными транскриптами, либо OpenAI / geko батчем) → роутер → TTS по предложениям (ElevenLabs Flash v2.5 / OpenAI / geko Tokay) → бесшовное воспроизведение в браузере. Текст — резервный канал. Без ключей используются речевые API браузера. |
| Выбор сценария на LLM-слое | Один потоковый вызов chat completions на реплику: в кэшируемом системном промпте — **весь каталог** (описания, границы `not_this_if`, слоты, действия) плюс состояние диалога; модель возвращает JSON, ключи которого упорядочены так, что **решение приходит раньше текста ответа** — сценарий известен на первых токенах, ответ генерируется в том же вызове. Энкодерного классификатора нет нигде. |
| Корректность | `python3 scripts/eval.py` прогоняет официальный `data/evaluate.py` по 104 dev-репликам через живой роутер. Лексический baseline без ключей: **90,4 % primary accuracy** (multi-intent recall 0,885, out-of-scope 4/4, unclear 3/3); LLM-роутер — основной путь (см. §7). |
| Панель трассировки | После каждой реплики: транскрипт, определённый язык и язык ответа, сценарий(и) с уверенностью и обоснованием, альтернативы, сигналы триажа, кандидаты ретривала, вердикт политики, слоты, действия (execute / preview / handoff), состояние диалога и «водопад» замеров (STT, триаж, ретривал, факты, **route**, TTFT модели, первый байт TTS, **первый звук**, всего) плюс задержка, измеренная в браузере. |
| Русский и казахский | Определение языка, включая смешанные фразы (`ru` / `kk` / `mixed` + доля казахского), ответ на доминирующем языке клиента, STT с переключением RU/KZ, голос TTS по языку. |

Опциональные пункты: **гибридная архитектура** (быстрый путь по лексическому шортлисту отвечает на очевидные информационные запросы за ~1 мс; LLM проверяет его в фоне, супервизор видит долю совпадений), **стек тем** (прерванные сценарии сохраняются и предлагаются позже), **переспрос вместо угадывания** (`SYS_UNCLEAR` с двумя наиболее вероятными вариантами), **передача оператору с контекстом**, **извлечение параметров** включая номера, произнесённые словами («плюс жеті, жеті жүз бір…» → `+77010000002`), **потоковая обработка** (частичные транскрипты, токены модели, TTS по предложениям), **определение тона** (сигнал upset/urgent → ответ сначала признаёт проблему), **статистика супервизора**, **редактирование каталога без разработчиков** (`PUT /api/catalog/scenarios/{id}` + reload, `data/` остаётся нетронутым), **подтверждение необратимых действий**, которое обеспечивает сервер, а не промпт.

## 3. Как работает решение (основной сценарий)

```
 микрофон ──PCM16──► WS ──► STT (realtime partials) ──► конец реплики (t0)
                                                            │
   ┌────────────────────────────────────────────────────────┘
   ▼
 1. ТРИАЖ  (детерминированно, <1 мс): язык ru/kk/mixed, сущности (телефон, ИИН, госномер,
            номер полиса/заявления, числа словами → цифры), срочность, маркеры нескольких
            намерений, да/нет, прощание, просьба оператора, признаки «не по теме», тон
 2. РЕТРИВАЛ (лексический BM25 по примерам сценариев + редактируемый лексикон, ~1 мс):
            ШОРТЛИСТ с оценками — подсказка модели и триггер быстрого пути, не решение
 3. ФАКТЫ  (тестовый бэкенд): шлюз подтверждения для превью-действия; идентификация клиента
            по только что названному телефону/ИИН; поиск упомянутого полиса/заявления → в промпт
 4. МАРШРУТ быстрый путь (информационный сценарий + явный лексический победитель + нет
            multi-intent/срочности) ─► шаблонный ответ; иначе LLM: системный промпт (каталог,
            правила, слоты, действия, примеры) + состояние + сигналы + факты →
            потоковый JSON {language, scenarios[{id, confidence, reason}], alternatives,
            is_continuation, slots, actions, handoff, reply} ← решение парсится, как только начался "reply"
 5. ПОЛИТИКА проверка ID, срочные первыми, пороги уверенности → proceed | clarify | handoff | out_of_scope
 6. ИСПОЛНЕНИЕ стек тем, слоты, read-only действия сразу (+ один дополнительный вызов модели,
            если ответу нужны их результаты), необратимые действия → PREVIEW (ждём подтверждения),
            handoff → очередь оператора
 7. ГОЛОС   предложения ответа → поток TTS → браузер (первое предложение звучит, пока генерируется остальное)
 8. ТРАССА  всё выше + замеры → панель, JSONL-хранилище, статистика супервизора, поток отладочных событий
```

Правило безопасности обеспечивает сервер: `create_policy`, `cancel_policy`, `create_claim`, `book_appointment`, … выполняются **только** если на предыдущей реплике было превью ровно этого действия, а текущая реплика клиента — подтверждение.

## 4. Технологии

- **Backend:** Go 1.26, роутер `chi`, `coder/websocket`; без БД (сессии в памяти + JSONL-журнал трасс в `var/`).
- **Frontend:** Next.js 16 (App Router, TypeScript), Tailwind CSS v4, `lucide-react`; захват микрофона через Web Audio worklet, энергетический VAD, потоковое PCM-воспроизведение, Web Speech API как резерв.
- **AI:** любой OpenAI-совместимый chat API для роутера (по умолчанию OpenAI `gpt-4.1-mini`; Groq / OpenRouter / Ollama через `LLM_BASE_URL`); STT: ElevenLabs Scribe v2 realtime + batch, OpenAI `gpt-4o-mini-transcribe`, geko Seta (`seta-kk-ru-v2`, OpenAI-совместимый эндпоинт); TTS: ElevenLabs Flash v2.5 (+ `eleven_v3` для казахского), OpenAI `gpt-4o-mini-tts`, geko Tokay (`tokay-kk-v1`).
- Сторонние компоненты: [THIRD_PARTY.md](THIRD_PARTY.md). Техническая спецификация и контракт API: [docs/SPEC.md](docs/SPEC.md).

## 5. Архитектура

```
frontend (Next.js :3000)  ── REST ──►  backend (Go :8080)
   Call · Supervisor · Eval            ├─ internal/triage      детерминированный слой 1
   Catalog · Debug                     ├─ internal/retrieval   BM25-шортлист + config/lexicon.json
   ◄── WS: события + PCM-аудио ──      ├─ internal/router      промпт, потоковый парсер, политика, mock-роутер
                                       ├─ internal/dialog      движок: состояние, факты, исполнитель, поток TTS
                                       ├─ internal/mockbackend actions.json над mock_backend.json + база знаний
                                       ├─ internal/stt, tts    провайдеры (ElevenLabs, OpenAI-совместимые, mock/browser)
                                       ├─ internal/store       сессии + traces.jsonl + статистика супервизора
                                       └─ internal/eval        оценка на dev-наборе (метрики как в evaluate.py)
```

## 6. Требования

- Docker 24+ с Compose v2 — **или** Go 1.26+, Node.js 20+ и Python 3 (скрипты); `ffmpeg` нужен только для перегенерации тестовых записей.
- **API-ключи для запуска и проверки не нужны**: без ключей бэкенд использует детерминированный лексический роутер, а браузер — своё распознавание/синтез речи (Chrome). Ключи включают LLM-роутер и серверные STT/TTS (см. §8).

## 7. Установка и запуск

```bash
git clone https://github.com/BAITC-Hacks/hack-9dd7b5f3-plus.git
cd hack-9dd7b5f3-plus
cp .env.example .env        # работает как есть (без ключей); добавьте ключи для LLM-пути
docker compose up --build   # backend http://localhost:8080, frontend http://localhost:3000
```

Без Docker (два терминала или `make dev`):

```bash
cd backend && go run ./cmd/server          # читает ../.env, порт 8080, данные из ../data
```

```bash
cd frontend && npm ci && npm run dev       # http://localhost:3000 (API на <host>:8080 по умолчанию)
```

Порты заняты? `BACKEND_PORT=8090 FRONTEND_PORT=3001 docker compose up --build` (затем откройте :3001, а для сборки фронтенда задайте `NEXT_PUBLIC_API_URL=http://localhost:8090`).

### Рекомендуемые ключи для полного режима
`OPENAI_API_KEY` (роутер `gpt-4.1-mini`, STT `gpt-4o-mini-transcribe`, TTS `gpt-4o-mini-tts`) **и/или** `ELEVENLABS_API_KEY` (realtime-STT с промежуточными транскриптами — самый быстрый путь — и TTS Flash v2.5). При обоих ключах по умолчанию: LLM — OpenAI, STT — ElevenLabs realtime, TTS — ElevenLabs. Для включения LLM-роутера задайте `LLM_PROVIDER=openai`.

## 9. Как проверить решение

1. **Поговорите с роботом.** Откройте фронтенд → *Call*. Нажмите микрофон (авто-VAD) или удерживайте его (push-to-talk) и скажите, например: «Здравствуйте, я вчера оплатил полис, деньги списались, а полиса нет… и ещё адрес поменять надо». Ожидаемо: два сценария — `SC30` (проблема с оплатой), затем `SC29` (изменение контактов), голосовой ответ на русском, панель трассировки с обоснованием, альтернативами и водопадом замеров. Затем: «Сәлеметсіз бе, полисім жарамды ма?» → `SC25`, ответ на казахском. Затем назовите телефон из кита («телефон плюс семь семьсот один ноль ноль ноль ноль ноль ноль семь») → клиент идентифицирован, робот использует его данные.
2. **Текстовый канал:** введите реплику в поле ввода — работает тот же конвейер.
3. **Точность на официальном dev-наборе:** при запущенном бэкенде `python3 scripts/eval.py` (печатает таблицу `data/evaluate.py` + перцентили задержки; то же самое — страница *Eval* → *Run evaluation*).
4. **Аудио-тесты:** `python3 scripts/audio_test.py` прогоняет [`tests/audio/*.wav`](tests/audio/) (3 записи: простая RU, смена темы RU, смешанная KK/RU) через STT → роутер → ответ и сверяет ожидаемые сценарии; `--save-replies` сохраняет озвученные ответы в `tests/audio/out/`. Без ключей транскрипт записи передаётся подсказкой, маршрутизация выполняется по-настоящему.
5. **Смотреть работу модели в реальном времени:** страница *Debug* или в терминале `curl -N http://localhost:8080/api/debug/events` — каждый шаг (триаж, кандидаты ретривала, промпт, токены модели, решение, действия, TTS) приходит событием. `GET /api/prompt` показывает системный промпт целиком. `python3 scripts/demo_dialog.py` прогоняет семь сценарных многоходовых диалогов (идентификация, смена и возврат темы, подтверждение необратимого действия, уточнение, мошенничество, смешанный язык, оператор) и печатает состояние после каждой реплики; `node scripts/ws_smoke.mjs tests/audio/02_ru_topic_switch.wav` прогоняет запись через голосовой WebSocket ровно как браузер и печатает события с таймингами (`--text "…"` для текстовой реплики, `--save reply.pcm` для сохранения аудио).
6. **Супервизор:** страница *Supervisor* — точность быстрого пути относительно фоновой проверки LLM, реплики с низкой уверенностью, передачи оператору, задержки p50/p90 по этапам и по путям; переход в любую сессию.
7. **Тесты:** `cd backend && go test ./...` (определение языка, числа словами, цены тестового бэкенда, потоковый парсер, лексический baseline ≥ 0,85, движок с имитацией потокового LLM включая дополнительный вызов после действий и шлюз подтверждения, клиенты провайдеров против фейковых серверов).

### Задержка
Замеряется на сервере по этапам и показывается в трассе; `route` = конец реплики → распарсенное решение, `first_audio` = конец реплики → первый байт аудио. Браузер дополнительно измеряет «конец речи → первый воспроизведённый сэмпл». Маршрутизация без ключей занимает ~1 мс; с LLM решение обычно приходит через TTFT + ~40 токенов, а первое предложение озвучивается, пока генерируется остальной ответ. Реальные цифры зависят от провайдера и сети — панель показывает их честно, а выигрыш быстрого пути виден в статистике супервизора.

## 11. Ограничения

- Режим без ключей — это baseline: лексический роутер не понимает диалог глубже правил продолжения/подтверждения, а браузерное STT (Chrome) распознаёт один заданный язык — смешанные фразы лучше через серверное STT.
- Ориентиры по задержке — ориентиры: доминируют финализация STT и TTFT модели; realtime-STT и быстрый путь — два рычага, цифры показываются, а не обещаются.
- Казахский TTS: у ElevenLabs Flash v2.5 нет казахского голоса (русский голос читает казахскую кириллицу); для правильного казахского используйте `TTS_MODEL_KK=eleven_v3`, OpenAI TTS или geko Tokay.
- Тестовый бэкенд — в памяти; сессии — в памяти (трассы сохраняются в `var/traces.jsonl`). Эндпоинты супервизора без авторизации (рамки хакатона).
- Телефонный канал (SIP) не реализован.
